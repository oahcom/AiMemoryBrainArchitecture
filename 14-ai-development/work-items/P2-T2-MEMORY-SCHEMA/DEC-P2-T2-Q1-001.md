## 3. Why this option, in the deciding session's own reasoning

Recorded because a decision record that keeps only the verdict loses the ability to be revisited if its premises fail.

**Preserve established architectural authority.** Phase 1 already has a frozen domain model, a decided SQLite persistence boundary and seven implemented, verified tables. No demonstrated incompatibility justifies superseding that investment. The distinction between the decided SQLite persistence boundary and the abstract adapter trait contract — which remains `CANDIDATE` by its own text — is accepted as R1 recorded it. R1's correction that the six-table prompt schema versus the Phase 1 model is architectural tension rather than proven incompatibility is also accepted, and the stronger claim is not revived here.

**Transcript capture is a different domain responsibility.** An event log is not automatically a transcript retrieval system. Transcript capture needs explicit contracts for ordered conversation retrieval, role-based filtering, thread reconstruction, tool-call and tool-result pairing, source identity and provenance, and lifecycle/retention/deletion. Those responsibilities should not be silently imposed on the canonical memory persistence model.

**Derived signals must not become a second source of truth.** Derived signals should be reproducible from declared source dependencies, with validity tied to those dependencies rather than to the fact that a signal was once generated.

**Option A creates an unjustified architectural loss.** It becomes reconsiderable if a generic event stream is accompanied by a properly specified transcript capture interface — but that interface is precisely the responsibility Option C makes explicit rather than implicit.

**Option B is rejected.** There is insufficient evidence to supersede the frozen Phase 1 model and persistence boundary.

## 8. What P2-T1 implementation authorisation would require

Option C gives P2-T1 an architectural target. It does not give it an executable implementation contract. The remaining gate is **implementation-specific Owner authorisation against an adequately specified and verified contract**, in this order:

1. **Establish the canonical persistence boundary.** Specify how P2-T1 writes canonical memories and versions through the Phase 1 boundary, preserving immutable versions, CAS and atomic pointer advancement.
2. **Specify the transcript capture contract.** Event ingestion, ordering, role filtering, thread reconstruction, tool-call pairing, idempotency, provenance, lifecycle. It must be independently retrievable without treating the transcript as canonical memory.
3. **Specify derived projection semantics.** Source dependencies, projection versions, rebuild behaviour, stale-data handling, failure recovery. Qdrant must not silently become an alternative canonical system of record.
4. **Resolve applicable outstanding decisions.** Q11–Q14 through their appropriate authorities. Q12 in particular cannot be closed by this record's assumption. *Status, as at design-proposal.md §2i and not as at the date of this decision: Q13, Q12 and Q9 were decided there; Q11 was **partly** decided — its technical-admissibility half is settled (the index is data-neutral with respect to `versions` admissible rows and is necessary for the §8.4 composite foreign key to be expressible), while the authorisation half is **not** settled and stands with the Phase 1 contract's owner, who is `NOT_ASSIGNED`; Q14 remains held. This gate is therefore satisfied for three of the four and open for Q11's authorisation half and for Q14. A technical admissibility finding does not discharge an authorisation question, and this record does not treat it as having done so.*
5. **Produce implementation acceptance criteria and tests.** Duplicate event delivery, out-of-order delivery, partial failure, restart/recovery, concurrent updates, projection rebuilding, provenance integrity, context-injection correctness.
6. **Obtain a separate P2-T1 implementation authorisation.** The implementation Owner accepts the exact target contract, scope, test obligations and failure boundaries, recorded against the exact artefact version.
7. **Complete the normal convergence chain.** Implementation, verification, applicable review, Owner acceptance, PR/merge and registration, traceable. Development-baseline exclusions stay explicitly distinguished from production requirements.

**Until these gates are satisfied, P2-T1 remains `BLOCKED` for implementation authorisation.**

## 9. The weakest part of this ruling, recorded as the deciding session stated it

Option C assumes that separating transcript capture from canonical memory produces a cleaner architecture without introducing excessive synchronisation and lifecycle complexity. That is an architectural judgment, not an empirically demonstrated result.

Unresolved risks it does not retire:

- cross-layer consistency when transcript events produce canonical memories
- deletion and retention propagation across the two layers
- rebuilding derived signals after source changes
- preserving ordering and provenance across ingestion failures
- avoiding two competing representations of the same underlying fact

The responsibility boundary is judged correct. The eventual implementation is not thereby proven simple, efficient or operationally reliable. This record keeps that uncertainty rather than converting it into a completed technical verification.
