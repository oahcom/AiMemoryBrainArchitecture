# Executed prompt — AID-2026-059 / Issues #1029, #1058, #1061, #1063, #1071, #1074, #1076

## Standing constraints

The session was given three, and they governed every deliverable:

1. **Smallest edit that changes the reported behaviour.** No interface with one
   implementation, no factory for one product, no configuration for a value
   that never changes, no scaffolding "for later".
2. **Every fix carries a mutation check.** Revert the fix; the new test must go
   red, and the failing test must be the one that names the defect. A test that
   passes with the fix removed is not evidence.
3. **No behaviour change outside the named defect.** Suite counts never
   decrease; existing tests are never weakened or deleted.

Two more applied to the records: any figure quoted in a report must have been
produced by running the named command against that branch (`DECLARED_NOT_OMITTED`
in the other direction — do not describe work not done, and do not omit work
that was), and a deliberate omission must be stated as one rather than left to
read as an oversight.

## Per-Issue assignment

Each was dispatched to its own worktree, branched from `main` at `29eea143`,
with `git push` and `gh pr create` forbidden — the integration step is
centralised so that conflicting edits are ordered deliberately rather than by
merge order.

### #1029 — the protected set was never compared to the declared set

`scripts/check_declared_check_contexts.py` proved *declared → produced* (every
context §7 declares is produced by a job in this tree). The direction that
actually broke was *protected → declared*: three `Session Evidence*` contexts
were required on the platform while the Normative document said twelve, and the
checker printed PASS throughout.

Required: read the live protection payload; compare on `(context, app_id)` set
equality, not on names, because two Apps can publish the same context name;
keep the exit-code vocabulary `0` PASS / `1` VIOLATION / `2` INCOMPLETE, where a
transport failure is `2` and must never be `0`; keep the offline run able to
verify the forward half without claiming to have verified protection; make the
branch configurable with a default of `main` rather than adding a required
positional argument. Also replace the stale standing claim in
`AID-2026-061/session-evidence-wo01.md` that §7 "declares twelve" with a
pointer to §7 — a pointer does not go stale.

### #1058 — two holes in the workflow-shape guard

`NEEDS_KEY_RE = re.compile(r"^    needs:\s*\S")` required a value on the same
line, so YAML's block form — the spelling a person writes by hand — carried
exactly the dependency the guard exists to forbid and passed. Separately,
`REQUIRED_JOB_IDS` membership was bound by no test: deleting `"validate"` left
the gate green on the real workflow.

Required: detect the block form and the empty form; add a test whose failure is
caused by removing `"validate"` from the constant. **Measured result at
integration time: the block-form half had already been fixed independently on
`main` by `a316ff69` (merged as #1085) with the same matcher; only the
`REQUIRED_JOB_IDS` half was still open, so only that test was kept.**

### #1061 — check_09 keyed its fence on *write*, the issue asked for *cite*

The cumulative manifest made every PR that declares `AID-2026-059` responsible
for linking every Issue any earlier session attributed its entry to — a
requirement that grows by one Issue per session, forever. PR #1077 bounded it by
gating on `changed_paths`.

Required: verify that the bounded rule leaves no hole, and if it does, close it.
**The hole was real and was reproduced before delegation:** a PR can name
another session's evidence document in its own `Session evidence reference(s)`
field while writing nothing and linking none of the Issues that document is
attributed to. Required fix: change the predicate to the union — an entry
answers for its `issue_refs` when this PR *wrote* it **or** *cited* it — because
write-only admits borrowed evidence and cite-only admits rewriting a historical
entry's `issue_refs` without citing it.

### #1063 — the policy boundary had no reader in any test

`AI_SESSION_EVIDENCE_EFFECTIVE_AT_UTC` lives at
`.github/workflows/session-evidence.yml:12`. Changing it from
`2026-12-01T00:00:00Z` to `1999-01-01T00:00:00Z` left 94 tests green. The value
decides which PRs must declare and the wording of the exemption notice, so
moving it inverts the verdict for a whole class of PRs and fails in the
silent-pass direction.

Required: a test whose assertion depends on that literal; the 1999 mutation must
produce an `AssertionError` whose test name identifies the effective-time
mismatch; no YAML dependency (the shape guard deliberately avoids one); if
`support.py` keeps `2099-01-01T00:00:00Z`, comment that it exists only to build
the "not yet effective" world.

### #1071 — a 924-line checker with no caller

`scripts/check_traceability.py` is executed only by its own unit test. Four
properties that `INDEX.md:124` and the manifest identity rule state have never
been enforced against the tree: no `AID` in two `INDEX.md` rows, `work_item_id`
equal to its directory name, every row resolving to a manifest, every manifest
having a row. The checker cannot currently run at all, because it requires
`00-governance/requirements-registry.yaml`, which does not exist.

Required: do **not** create the registry (#266/OD-23's scope). Make the
INDEX/manifest half runnable without it, run it inside a job that already
produces a required context, and prove with two negative tests on the real
command path that the assertions bite. Failing loudly on a missing registry is
correct (#926) and must not be regressed.

### #1074 — the gate judged a body that could change after the run

`pull_request` without `types:` excludes `edited`, and the validator reads
`pr.body` live. A body edit after a run therefore left a green tick certifying
text that no longer existed — and `Session Evidence` is a required context, so
that tick is what authorised the merge. Measured three times in one hour in this
repository including one fail-open.

Required, both halves: re-run on `edited`; and write a digest of the exact body
string the validator saw into the job summary, so a later edit is detectable.
The digest must be emitted by the workflow, not the validator, because the
validator runs from the base revision and a PR must not be able to change its
own judging rules. A `null` body is a legitimate input and must digest as the
empty string rather than crash.

### #1076 — the anti-fail-open precondition was a tautology

`if set(linked) != set(ctx.issues)` compared `parse_related_issues(ctx.body)`
against `ctx.issues`, which `_load_context` fills from that identical
`pr["body"]` string, and `_run_checks` never reassigns it. The condition was
`X != X`. Measured: deleting the block leaves the suite green (it cannot bite);
replacing it with `if True:` makes 46 tests fail (the line is executed). Dead
code that reads as an active defence.

Required: replace it with a check that compares a resolved fact against an
unresolved one — raise when the Related field parses and resolution yields
nothing; add one test that goes red when the precondition is deleted; leave the
`#1003` behaviour and `_historical_not_applicable` alone.
