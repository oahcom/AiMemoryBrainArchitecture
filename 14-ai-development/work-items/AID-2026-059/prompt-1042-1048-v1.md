# AID-2026-059 session prompt — Issues #1042, #1045, #1047, #1048

The assignment as received by the implementing session: close the four
residuals left open after Issue #799's gate landed. Each residual is a defect
where a check reported success over a fact it never read. The four live in
different files, so they were repaired in one branch and reported as one
bundle.

## Task

Repo: `oahcom/AiMemoryBrainArchitecture`. Work in a git worktree of
`fix/session-evidence-residuals`, based on `main` at `adb31099`, and touch
nothing outside it.

The facts to re-verify rather than trust are stated per Issue below.

## Issue #1042 — the manifest was chosen by a body-wide regex

`_manifest_path_from_pr` resolved the Work Item manifest by regex-searching
the whole pull-request description for the first `AID-\d{4}-\d{3}`. Prose
such as "This supersedes AID-2026-003." above the declaration therefore
outranked the declaration: a body declaring `AID-2026-055` validated
`AID-2026-003`'s manifest, and a body with no declaration at all passed as
long as some identifier appeared anywhere in it.

Required behaviour:

- Read the `Work Item ID` field through `_extract_field`, the same path every
  other required field already takes.
- Accept the literal `NONE` only when the body also declares
  `AI-assisted work: NO`. A `YES` declaration owes a manifest-held
  `session_evidence` entry, so a pull request that declares `YES` must name a
  work item.
- Reject a value that is neither `AID-YYYY-NNN` nor `NONE`.
- Return `str | None`; `None` means no manifest applies, and in that case
  print
  `AI-SESSION-EVIDENCE: PRESENT (no Work Item declared; manifest and session-evidence entry checks not applicable)`
  so a green build is not mistaken for a validated one.

Do NOT add a `work item` alias to `FIELD_ALIASES`. A `## Work Item` heading
normally carries a task title, and aliasing it would make the gate read a
title as an identifier. The two test fixtures that used that heading are
corrected to `## Work Item ID` instead.

## Issue #1045 — the violation message named the one correct line

`scripts/check_session_evidence_workflow_shape.py::_checkout_refs` matched
`ref:` to decide that a checkout step was an offender, then appended the line
matching `uses: actions/checkout` — the one line in the step that is correct.
A reader sent to the cited line found no `ref:` there.

Required behaviour:

- Append the offending `ref:` line, defaulting to the `uses:` line so the
  expression stays total.
- Add a test asserting the full
  `ref: ${{ github.event.pull_request.base.sha }}` value, because the
  pre-existing `assertIn("ref:", message)` was satisfied by the word `ref:`
  in the prose and could not tell the two behaviours apart.

## Issue #1047 — a second, unvalidated copy of the same digest

`prompt_id` / `prompt_sha256` at the top of a manifest are a second copy of
the fact `executed_prompt_sha256` records in the `session_evidence` entry.
Nothing reads the top-level pair, so the two could drift without an error.

Decision: annotate the top-level pair as non-normative in the YAML block and
in the section 3.2 prose, in both languages. Do not delete it — historical
manifests carry it and must not be rewritten. Separately, add a check-number
table to the top of `validate.py`: the surviving numbers are
`01/02/03/04/06/09/11` (`05` and `08` were never written; `07` and `10` were
deleted in #1031), nothing was renumbered, and the table says why the gaps
remain.

## Issue #1048 — no root-level admission rule

`scripts/ci/check_repository_hygiene.py` admitted any new root-level file
whose suffix was common, which is how `_pr_body.md` and `_tmp_pr_create.py`
reached `main` while the gate printed PASS.

Required behaviour:

- Refuse a new path whose parent is the repository root and whose name begins
  with `_` or `.`.
- Keep the rule root-scoped: a leading underscore in a subdirectory is
  ordinary (a private module, an internal fixture).
- Keep `/_dm.txt` in `PROHIBITED_PATHS` for its own reason, and keep the two
  rejection reasons distinguishable in the message.
- Bump `CHECK_VERSION` to `2026-11-24.8`.
