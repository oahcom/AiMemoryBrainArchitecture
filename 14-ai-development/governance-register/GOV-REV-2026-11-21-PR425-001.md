## 3. 负向执行（变异测试）——本次审查的主要产出

「10 个测试通过」本身不证明测试有效。为区分「测试通过」与「测试能发现问题」，对 `memory_compiler.py` 注入三个变异体，每个变异后重跑同一套测试：

| # | 变异 | 预期 | 实测 | 判定 |
|---|---|---|---|---|
| M0 | 无（基线） | 通过 | `Ran 10 tests` / `OK`，exit 0 | 基线成立 |
| M1 | `sha256_text` 改为返回常量摘要（忽略输入） | 失败 | `FAILED (failures=1)`，exit 1 | **KILLED** |
| M2 | `_required` 去掉 `.strip()` 判空（接受空串） | 失败 | `FAILED (failures=1)`，exit 1 | **KILLED** |
| M3 | `_digest` 去掉 `_SHA256.fullmatch` 校验（接受任意字符串） | 失败 | `Ran 10 tests` / **`OK`**，exit 0 | **SURVIVED** |

M3 的具体变异：

```python
# 原
def _digest(value: str, field: str) -> str:
    if not isinstance(value, str) or not _SHA256.fullmatch(value):
        raise StageError(f"INVALID_{field.upper()}")
    return value

# 变异后
def _digest(value: str, field: str) -> str:
    if not isinstance(value, str):
        raise StageError(f"INVALID_{field.upper()}")
    return value
```

**测试全部通过。** 即：`test_validation_rejects_digest_mismatch` 只覆盖了「摘要与内容不匹配」，没有覆盖「摘要本身不是 64 位十六进制」。这两件事在契约上是不同的失败模式（前者是内容完整性，后者是输入格式合法性），而后者现在没有任何测试保护。
