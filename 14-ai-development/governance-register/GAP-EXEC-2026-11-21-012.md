## 1. 环境障碍及其解除

### 1.1 障碍

`GAP-BASELINE-002.md` §Measurement method 记录：

> This machine's `gcc` is an incomplete MinGW install: `gcc.exe` exists but `cc1` does not, so no C code compiles. Any crate that pulls in `libsqlite3-sys` (via `rusqlite` with the `bundled` feature) cannot be built or tested here.

实测复现：

```
gcc.exe: fatal error: cannot execute 'cc1': CreateProcess: No such file or directory
error occurred in cc-rs: command did not execute successfully
  "gcc.exe" ... "-c" "sqlite3/sqlite3.c"
```

### 1.2 解除方式

本机存在完整的 `zig`（`ziglang` Python 包内置 `zig.exe`）。用 `zig cc` 作为 C 编译器：

```bash
export CC="<path>/zigcc.bat"     # 转发到 zig cc
export AR="<path>/zigar.bat"     # 转发到 zig ar
cargo test --workspace
```

`zigcc` 包装器做两件事，都是必要的：

1. `--target=x86_64-pc-windows-gnu` → `--target=x86_64-windows-gnu`（zig 不接受前者）
2. 追加 `-fno-sanitize=undefined`（`zig cc` 在 `-O0` 下会给 `sqlite3.c` 注入 UBSan 调用，而 rustc 链接行不含 ubsan runtime，否则 undefined reference）

**这是环境修补，不是代码修改。** 仓库内容未改动一个字节。
