# Project Redlines — AiMemoryBrainArchitecture

- Registry ID: PR-2026-11-16
- Version: 0.1.0
- Status: **PROPOSED — NOT APPROVED; NOT ACTIVE**
- Rule: These are project-level redline candidates. A violation cannot be waived by a module Owner alone.
- Authority: Project Governance Authority = **GOVERNANCE-OPEN**.

## PR-01 — Brain Independence
**Rule:** Brain must not become an Agent Framework feature or subordinate private-memory plugin. **Scope:** product, architecture, persistence, APIs, deployment. **Forbidden:** framework-private state as sole authority; framework-specific coupling in canonical semantics. **Allowed:** optional adapters. **Violation:** replacing framework loses canonical memory. **Impact:** Critical. **Check:** framework substitution/export/import conformance. **Handling:** stop affected design/release; open project finding and migration plan. **Change:** Project Governance Authority. **Exception:** only time-bounded compatibility bridge, approved by project authority, with portable canonical store, exit plan and no data lock-in.

## PR-02 — Model Independence
**Rule:** core memory behavior must not depend on one LLM/vendor. **Scope:** domain, compiler, retrieval, context, protocol. **Forbidden:** model-specific output as sole canonical schema or required proprietary inference API. **Allowed:** pluggable model-assisted extraction/ranking with deterministic contracts/fallbacks. **Violation:** model/vendor replacement breaks memory access or lifecycle. **Impact:** Critical. **Check:** multi-model/no-model contract tests and export. **Handling:** block contract freeze. **Change:** Project Governance Authority. **Exception:** bounded optional accelerator only; disclose degradation, portability and sunset plan.

## PR-03 — Responsibility Boundary
**Rule:** Brain does not own Agent planning, decision making, tool execution or external action policy. **Scope:** APIs, runtime, adapters, product claims. **Forbidden:** browser/terminal/tool executor, Agent planner, workflow orchestrator or action authority inside Brain. **Allowed:** retrieval/activation recommendations and managed context. **Violation:** Brain selects and executes external actions. **Impact:** Critical. **Check:** responsibility matrix, API review, threat/authority review. **Handling:** reject scope expansion. **Change:** Project Governance Authority. **Exception:** none for core product; optional external integration must remain separately owned and authorized.

## PR-04 — Canonical Memory Authority
**Rule:** only D-designated canonical authority operations may mutate Canonical Memory. **Scope:** all producers, stores, indexes, compilers, admin paths. **Forbidden:** direct writes by E/F/G/H/C, index rebuild or storage utility bypassing D's contract. **Allowed:** proposals and writes through D-authorized interfaces. **Violation:** compiler writes canonical row directly. **Impact:** Critical. **Check:** write-path inventory, capability/ACL review, integration tests. **Handling:** block release, quarantine path, audit and repair. **Change:** Project Governance Authority with D owner concurrence; module Owner cannot waive. **Exception:** narrowly scoped migration/recovery procedure only, approved by project authority and D/I, fully audited and time-limited.

## PR-05 — Memory Context Management
**Rule:** Brain must manage its explicitly owned Memory Context region, not degrade to passive Recall. **Scope:** runtime, context APIs, adapters. **Forbidden:** retrieval-only architecture with no versioned add/update/remove/replace/reorder/expire/compact/reconcile/delivery/applied evidence. **Allowed:** Agent owns other prompt regions. **Violation:** Brain can return memories but cannot govern its managed region. **Impact:** Critical. **Check:** context lifecycle and delivery conformance. **Handling:** block product acceptance. **Change:** Project Governance Authority with G/C/H owner review. **Exception:** temporary adapter limitation only if capability gap is explicit, scoped and expiry-bound; cannot waive product capability.

## PR-06 — Managed Region Ownership
**Rule:** Brain may mutate only explicitly designated, authorized Brain-managed regions. **Scope:** prompt assembly, adapters, synchronization. **Forbidden:** overwrite System Instructions, Developer Instructions, User Original Input or Agent Safety Policy. **Allowed:** operate in dedicated region with versioned boundaries. **Violation:** Replace operation overwrites developer instruction. **Impact:** Critical. **Check:** region ACL and adapter adversarial tests. **Handling:** fail closed, suppress delivery, incident review. **Change:** Project Governance Authority with C/G/H/I concurrence. **Exception:** no exception for protected-region writes; region assignment may change only through explicit authority and audit.

## PR-07 — Untrusted Memory
**Rule:** Memory, Evidence, summaries, historical outputs and external content are data, never instruction authority. **Scope:** ingestion, compilation, retrieval, summarization, context and inference boundary. **Forbidden:** execute embedded instructions, elevate memory to system/developer role, allow provenance laundering. **Allowed:** quote/cite/label as untrusted content. **Violation:** retrieved memory tells adapter to ignore safety policy and is injected as instruction. **Impact:** Critical. **Check:** poisoning, indirect prompt injection, compaction laundering and cross-scope adversarial tests. **Handling:** quarantine, trace lineage, suppress affected derivatives, security incident process. **Change:** Project Governance Authority with I/C/E/F/G/H review. **Exception:** none for instruction elevation.

## PR-08 — Identity and Authorization
**Rule:** authenticated identity is distinct from payload identity; Scope is not Permission. **Scope:** every protected read/write/delivery/forget/administrative boundary. **Forbidden:** trust payload ActorRef/producer ID as authentication; treat scope membership as grant; ignore revocation/epoch. **Allowed:** authenticated issuer-bound principal, explicit permission and delegation checks. **Violation:** caller supplies `principal_id=admin` and gains access. **Impact:** Critical. **Check:** negative authn/authz, delegation, revocation and stale-epoch tests. **Handling:** deny by default, audit, revoke and investigate. **Change:** Project Governance Authority with B/I/H concurrence. **Exception:** no exception for unauthenticated protected access; emergency break-glass requires independently authenticated, narrow, audited and expiring grant.

## PR-09 — Evidence Integrity
**Rule:** preserve source, lineage, conflict and epistemic status; never fabricate evidence or silently overwrite conflicts. **Scope:** compiler, canonical model, retrieval, summaries, audit. **Forbidden:** claim inference as verified fact; detach evidence/provenance; erase conflict history without governed resolution. **Allowed:** explicitly labeled inference/summary with traceable sources and confidence. **Violation:** unsupported extraction published as confirmed fact. **Impact:** High/Critical depending on downstream use. **Check:** lineage completeness, conflict tests, evidence-reference validation and audit sampling. **Handling:** quarantine/retract derived item, preserve audit trail, repair downstream derivatives. **Change:** Project Governance Authority with B/D/E/I review. **Exception:** only presentation-level omission that retains canonical evidence and provenance; no exception to fabrication prohibition.

## PR-10 — Forget Completeness
**Rule:** forgotten memory must not reappear through retry, replay, recompile, index rebuild, cache, Context delivery, reconnect or restore. **Scope:** all producers, consumers, projections, adapters, external copies and backups. **Forbidden:** late derivative publication after fence; treating unknown/offline as confirmed; restore without reapplying Forget suppression. **Allowed:** asynchronous cleanup after immediate logical suppression, with typed target status and explicit residual exception policy. **Violation:** DLQ replay republishes forgotten derivative. **Impact:** Critical. **Check:** cross-module race matrix, fault injection, restore drills, target inventory and proof vector. **Handling:** block Forget completion/release; suppress, reconcile and incident response. **Change:** Project Governance Authority with D/E/F/G/H/I concurrence. **Exception:** only I-governed residual exception, approved by project authority, named targets, explicit risk, scope, expiry, compensating controls and user-visible status; cannot claim full erasure.

## PR-11 — State Integrity
**Rule:** Accepted, Committed, Delivered, Applied, Suppressed, Deleted and Physically Erased are distinct states/evidence. **Scope:** receipts, canonical store, context delivery, adapters, Forget and restore. **Forbidden:** ACK conflation or false global completion. **Allowed:** typed state machines with explicit evidence and scope. **Violation:** Accepted receipt reported as canonical commit or Adapter-local ACK as global erase. **Impact:** Critical. **Check:** transition invariants and negative conformance tests. **Handling:** correct status, reopen gate, preserve audit. **Change:** Project Governance Authority with relevant state owners. **Exception:** none for semantic conflation; reporting aggregation may summarize only if underlying typed states remain available.

## PR-12 — Verification Integrity
**Rule:** documentation, author self-review and static inspection do not prove implementation, integration, security, performance or operational readiness. **Scope:** all acceptance claims. **Forbidden:** claim tests ran without evidence; treat file existence or commit count as gate pass. **Allowed:** clearly scoped static/design verdict. **Violation:** “Forget safe” declared based only on design prose. **Impact:** High/Critical. **Check:** evidence ledger with reproducible test IDs, commit, environment, results and reviewer. **Handling:** downgrade claim, reopen gate and require missing evidence. **Change:** Project Governance Authority. **Exception:** no exception to truthful evidence classification.

## Exception protocol

Every proposed exception must include: redline ID; exact rule and rationale; alternatives considered; affected assets/modules/users; threat and residual risk; named approvers; compensating controls; start/end time; revocation trigger; audit/evidence; rollback/exit plan. Approval requires Project Governance Authority and all directly affected authority owners; I/security concurrence is mandatory for security, identity, Forget, retention or evidence exceptions. Module Owner alone cannot approve. No exception may authorize protected-region writes, instruction elevation, fabricated evidence, unauthenticated protected access, state conflation or false verification claims.

## Change control

Redline changes require project-level change request, impact analysis, explicit versioning and approval by the Project Governance Authority. Preserve superseded rules and waivers. All entries remain PROPOSED until formally approved.
