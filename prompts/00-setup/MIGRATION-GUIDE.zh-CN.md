# 提示词 v1 → v2 迁移指南

- Guide ID：AI-PROMPT-MIGRATION-001
- Version：1.0
- Status：PROPOSED — 尚待治理采纳

**English counterpart:** [MIGRATION-GUIDE.md](MIGRATION-GUIDE.md)

## 1. 迁移政策
v2 将提示词结构从十五个强制标题压缩为七个核心章节，但不删除适用的治理义务、证据、审批或历史记录。

- 既有已执行 v1 提示词继续有效且不可变。
- 不得批量重写活动中的提示词。只有在需要且获准进行新执行/新版本时，才创建 v2 副本。
- 保留原提示词、版本、SHA-256、Issue/PR 链接、Commit、审查和验收记录。
- 如果源字节或历史摘要无法验证，记录 NOT_VERIFIED；不得猜测。
- 七个章节只是提示词布局。Work Item Manifest、证据包、全局提示词、GOV-DOC-001 和会话 Closeout 仍然适用。

## 3. 迁移但不豁免
### 安全、故障、并发、恢复和兼容性（v1-11）
这些要求没有从治理中删除。提示词不再要求在任务尚未明确前进行推测性的穷尽分析。Owner 应在设计、实现、验证和审查门禁处理适用风险。R2/R3 及安全/数据完整性要求保持不变。

### 双语文档（v1-15）
双语工作由 GOV-DOC-001 和 GLB-DOC-001 管理，而不是由单独的第十五个标题管理。提示词仍必须识别受影响的中英文路径；架构语义变化时，必须在范围/验收中包含双语工作并提供一致性证据。除非存在正式批准且有期限的 STALE 例外，否则缺失对应文档仍属于 NOT DONE。

### 测试与证据（v1-10、v1-13）
P0/P1 是适用性分类，不是跳过必需检查的许可。早期架构探索阶段可以尚未确定准确命令，但必须在验证门禁前明确。每项已执行检查都要记录其测试 SHA 和结果。未运行的必需检查必须标记 NOT RUN，绝不能标记 PASS。

### SHA-256 与 Git 可追溯性（v1-1、v1-13）
在有要求时，Git Commit/Blob 标识不能替代准确执行提示词快照的 SHA-256。将提示词摘要存入 Work Item Manifest/证据包。Commit SHA、最终 Head SHA、变更路径、读回及审查/验收记录仍是 P0。

## 4. 迁移步骤
1. 识别源提示词，并验证 Work Item、Owner、执行状态、源修订和历史摘要。
2. 原样保留源文件。仅为新的/获授权执行创建新的 v2 工件，并链接到源版本。
3. 按映射表迁移字段。将每项要求分类为：保留在核心章节、由全局政策管理、说明原因后不适用，或尚未解决。
4. 重新检查 Owner 权限、允许/禁止路径、依赖 SHA、可观测验收、证据和停止条件。
5. 检查 GOV-DOC-001 适用性、成对路径、一致性 Manifest 和覆盖登记。
6. 执行前，对新提示词准确字节计算并独立验证 SHA-256；将结果记录到 Manifest。
7. 完成必需提示词审查和 Owner 授权。只有适用的 Ready 门禁通过后才能开始。
