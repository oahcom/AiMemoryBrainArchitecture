## 2. 政策要求（Owner 裁定 A）

规范 Markdown 允许两种配对形态，**二者等价，不构成双重义务**：

| 形态 | 组成 |
|---|---|
| S-并排 | 同目录 `X.md` + `X.zh-CN.md` |
| S-镜像 | 根正文 + `docs/en/X.md` + `docs/zh-CN/X.md` |

约束：

1. 并排必须是**同目录、同 stem** 的精确配对；
2. 不得以「任意含 `.zh-CN` 的文件名」替代；
3. 不得只提供一侧语言；
4. 既有豁免（`EMBEDDED_BILINGUAL_SOURCES`、`PAIR_EXEMPT_PREFIXES`）继续生效，**不得扩大**；
5. 两种形态是替代关系，不是叠加要求。

## 3.5 补充实测：既有 `side_by_side_partner` 为何不能直接复用

在真实克隆上只放 `14-ai-development/zzp.md` + `zzp.zh-CN.md`（不放 `.en.md`、不放镜像），直接调用三个解析器：

```json
"14-ai-development/zzp.md":        {"side_by_side": null, "mirror": null, "counterpart_14": null}
"14-ai-development/zzp.zh-CN.md":  {"side_by_side": null, "mirror": null, "counterpart_14": null}
"14-ai-development/zzp.en.md":     {"side_by_side": "14-ai-development/zzp.zh-CN.md", ...}
"04-memory-compiler/zzq.md":       {"side_by_side": null, "mirror": null, "counterpart_14": null}
"04-memory-compiler/zzq.zh-CN.md": {"side_by_side": null, "mirror": null, "counterpart_14": null}
```

**关键观察：`X.md` 与 `X.zh-CN.md` 互不识别——两个都返回 `null`。**

原因在 `side_by_side_partner` 的分支：

```python
elif source.endswith(".md"):          # X.md 只找 X.en.md
    cand = stem + ".en.md"
elif source.endswith(".zh-CN.md"):    # X.zh-CN.md 只找 X.en.md
    cand = stem + ".en.md"
```

**两个分支都只找 `.en.md`，从不互相查找。** 所以：

- `X.md` + `X.zh-CN.md` → 双方都解析不出；
- `X.md` + `X.en.md` → `.en.md` 侧能解析到 `.zh-CN.md`（若存在）或 `.md`，但 `.md` 侧仍只找 `.en.md`，**不对称**。

这解释了为什么「并排」在缺口扫描中从未生效：**不是被 `resolved_14` 拦住，而是这对文件名根本不被任何一个解析器认作配对。**

因此 §4 的建议不是「扩大既有函数的作用域」，而是**新增一个对称的同目录解析器**。

### D-11..D-14 diff 判定域（`check_normative_pairing`）——§4.5.2c 补充

上述 D-1..D-10 全部只调用 `current_bilingual_gaps()`。但 §4.5.2c 已实测：**只改缺口扫描时，#433/#435/#436 仍为 `EXIT=1`**，因为 `check_normative_pairing()` 另有一套要求。

| 编号 | 输入（PR diff 内容） | 预期 |
|---|---|---|
| D-11 | `04/X.md` + `04/X.zh-CN.md` 同时新增，PR 正文含 `BILINGUAL-MANIFEST: COMPLETE` | `check_normative_pairing` 返回空错误列表 |
| D-12 | 仅新增 `04/X.md`（无 `.zh-CN.md`、无镜像） | 报 `requires all counterparts changed in this PR` |
| D-13 | `04/X.md` 新增，但 `04/X.zh-CN.md` 未在本次 diff 中（已存在于树） | 仍报错（要求同 PR 变更） |
| D-14 | `04/X.md` + `04/X.zh-CN.md` 新增，但 PR 正文无 `BILINGUAL-MANIFEST: COMPLETE` | 不检查配对（`normative_changes and complete` 前置条件不成立），但另有 manifest 错误 |

D-13 与 D-14 是关键边界：前者证明「配对必须是本次变更」，后者证明「无 manifest 时该判据整体短路」。两者都不应被实施者改动。

## 4. 建议的实现形态（供审查者评估，不预设）

**要点：不要改 `resolved_14`。** 它是 `14-ai-development` 的**变更路径**解析器，与缺口扫描的语义不同（§1 实测）。在缺口扫描里复用它正是初版判断出错的原因。

建议引入一个独立的、只服务缺口扫描的判定：

```python
def has_pairing(source: str) -> bool:
    """True if source has a same-directory same-stem side-by-side partner,
    or both docs/ mirrors exist."""
    english = REPO_ROOT / "docs" / "en" / source
    chinese = REPO_ROOT / "docs" / "zh-CN" / source
    if english.is_file() and chinese.is_file():
        return True
    return side_by_side_same_dir(source) is not None
```

`side_by_side_same_dir` 必须与既有 `side_by_side_partner` 区分开，因为后者：

- 对 `.md` 只找 `.en.md`（不找 `.zh-CN.md`）；
- 用 `ROOT` 而非同目录约束。

新的判定需要满足：

| source 后缀 | 找 | 约束 |
|---|---|---|
| `.md` | `<stem>.zh-CN.md` 或 `<stem>.en.md` | 同目录 |
| `.zh-CN.md` | `<stem>.md` 或 `<stem>.en.md` | 同目录 |
| `.en.md` | `<stem>.md` 或 `<stem>.zh-CN.md` | 同目录 |

**并且两侧必须互为对方**（D-3 的要求），即 `partner(partner(x)) == x`。

### 4.1 更正：必须改两处，不是一处

§4 初稿只说「引入一个独立的、只服务缺口扫描的判定」。**这不够**（§4.5.2c 实测）。

裁定 A 的完整实现需要两处调用同一个解析器：

| 位置 | 判定域 | 现状 | 改动 |
|---|---|---|---|
| `current_bilingual_gaps()` | 全树 | 只认 `docs/en` + `docs/zh-CN` | 并排解析非空则视为已配对 |
| `check_normative_pairing()` | diff | 非 14 根无条件要求 `docs/en` + `docs/zh-CN` 同 PR 变更 | 并排解析非空则用它作为唯一 partner |

两处的语义差别必须保留：

- 缺口扫描问「这个文件在树上有没有配对」；
- 规范变更配对问「这次改动有没有同时改配对侧」。

若只改前者，PR 仍会因「配对侧未在本次变更中」被拒（`EXIT=1`）；若只改后者，主干会因新文件成为缺口而变红（`EXIT=2`）。**两者必须同时改，且必须与基线收缩在同一 commit。**

### 4.2 第三条强制规则：已解决的缺口必须同步移出基线

实测（§4.5.2c 之前的一次尝试）发现门禁还有一条我未记录的规则：

```python
gap_now = current_bilingual_gaps()
new_gaps = sorted(gap_now - baseline)
resolved = sorted(baseline - gap_now)
if new_gaps:
    return 2      # 新缺口 → 红
if resolved:
    print(f"::error::Resolved bilingual gap must be removed from "
          f"scripts/bilingual-baseline.txt: {path}")
    return 2      # 已解决的缺口未从基线移除 → 同样红
```

**棘轮是双向强制的**：既不许多，也不许少。

实测确认：只装门禁变体、不收缩基线，空 diff 立刻 `EXIT=2`，并逐条列出 29 个「Resolved bilingual gap must be removed」。

因此实施必须是一次**原子提交**：

```
scripts/check_bilingual_docs.py        +~20 行（两处 patch + 一个解析器）
scripts/bilingual-baseline.txt          -29 行
```

分两次提交会在中间状态把 main 变红。这一点必须写进实施 PR 的说明，否则审查者可能批准一个「先改脚本、再改基线」的两步方案。

## 4.5 配对唯一性与对称性规则（应 Owner 要求补充）

Owner 指出 `partner(partner(x)) == x` 是必要条件但不足以定义全部合法情况，并给出建议：

> 允许合法的两文件配对；同一 stem 出现多于两个候选文件时，除非规格明确规定了可证明无歧义的三文件语义，否则拒绝自动配对并报告歧义。

**采纳该建议。以下是实测支撑。**

### 4.5.1 实测：三文件共存时既有解析器形成循环

同 stem 三个文件共存（`zz.md` / `zz.en.md` / `zz.zh-CN.md`），直接调用既有解析器：

```json
"04-memory-compiler/zz.md":        {"sbs": "04-memory-compiler/zz.en.md"}
"04-memory-compiler/zz.en.md":     {"sbs": "04-memory-compiler/zz.zh-CN.md"}
"04-memory-compiler/zz.zh-CN.md":  {"sbs": "04-memory-compiler/zz.en.md"}
```

`14-ai-development` 下完全同形。

三个后果：

1. **不对称**：`zz.md → zz.en.md`，但 `zz.en.md → zz.zh-CN.md`，所以 `partner(partner(zz.md)) = zz.zh-CN.md ≠ zz.md`。
2. **`.md` 与 `.zh-CN.md` 之间没有直接配对**：`zz.zh-CN.md` 找的是 `.en.md`，不是 `.md`。
3. **`.en.md` 是唯一被双向引用的文件**，成为事实上的枢纽——但它的两个「伙伴」互不相识。

若照搬这套逻辑实现裁定 A，`X.md` + `X.zh-CN.md` 的配对判定会依赖「是否存在一个 `.en.md`」这个与政策无关的第三方文件。**这是不可接受的耦合。**

### 4.5.2 规则

按 Owner 建议，规格采用**严格二元配对 + 歧义即拒绝**：

#### R-1 合法形态只承认两种

| 形态 | 组成 | 说明 |
|---|---|---|
| P1 | `X.md` + `X.zh-CN.md` | 同目录，同 stem |
| P2 | `X.md` + `X.en.md` | 同目录，同 stem |
| P3 | `X.md` + `docs/en/X.md` + `docs/zh-CN/X.md` | 镜像三件套 |

**不承认三文件并排形态（`X.md` + `X.en.md` + `X.zh-CN.md`）。**

#### R-2 唯一性

对任一 source，其 partner 必须**唯一**：

```
candidates(source) = { 同目录同 stem 的 .md / .en.md / .zh-CN.md 中存在者 } - {source}
```

- `|candidates| == 1` → 配对成立，且 `partner(partner(source)) == source` 必须为真；
- `|candidates| == 0` → 无并排配对，转而检查 P3 镜像；
- `|candidates| >= 2` → **歧义，判为缺口，并输出 `AMBIGUOUS_PAIRING` 报告项**。

#### R-3 不得以优先级掩盖歧义

禁止「优先选 `.zh-CN.md`」这类规则。理由：优先级会让同一棵树在增加一个文件后**静默改变**既有配对结果，而增量变更不会触发全量复核。

#### R-4 歧义的报告形态

歧义不应只表现为「缺口」，否则无法与「确实缺配对」区分。建议：

```
::error::Ambiguous bilingual pairing for <source>: candidates <a>, <b>
```

对应缺口集合仍包含该 source（保守处理：不因歧义放行）。

#### R-5 P3 与 P1/P2 的优先级

若同一 source 同时满足 P1 与 P3：

- 视为**合法**（P3 是更强的形态，`docs/` 两侧齐全）；
- **不报歧义**，因为 P3 不依赖并排候选的唯一性；
- 但需在报告中标注 `PAIRED_BY_MIRROR_AND_SIDE_BY_SIDE`，供审查者核对是否存在正文不一致。

#### R-6 存量兼容

既有文件若已是三文件形态（`X.md` + `X.en.md` + `X.zh-CN.md`），按 R-2 会被判歧义 → 计入缺口。

**这是有意为之**：它把存量中的歧义暴露出来，而不是静默接受。但为避免一次性制造大量新缺口，需在实施时：

1. 先统计存量中符合该形态的文件数量；
2. 若数量大于 0，则这些文件需**显式登记进 `EMBEDDED_BILINGUAL_SOURCES` 或基线**，并在报告中单列「存量歧义清单」；
3. 不得为了减少缺口数而放宽 R-2。

### 4.5.2a 存量实测（应 Owner 要求执行）

在真实克隆（`main` `c138654c94`，770+ 提交）上，对九个 `NORMATIVE_ROOTS` 逐一枚举同 stem 的 `.md` / `.en.md` / `.zh-CN.md`：

```
file kind counts: {'md': 233, 'zh': 7, 'en': 17}

stem shape distribution (kinds present -> number of stems):
  md          221
  en+md        11
  en+zh         6
  md+zh         1
```

**三文件并排形态（`md+en+zh`）在存量中的数量：0。**

因此：

| 问题 | 实测答案 |
|---|---|
| R-2 歧义规则会在存量中新增多少缺口？ | **0** |
| R-6 是否需要为存量歧义单列清单？ | **不需要**（无存量歧义） |
| 是否有文件同时具备并排与 P3 镜像（触发 R-5）？ | **有 1 个**（见下） |

#### 唯一的 R-5 先例

```
06-memory-context/phase-3.8.22-g-applied-persistence-idempotency-crash-restore-contract.md         35411 B
06-memory-context/phase-3.8.22-g-applied-persistence-idempotency-crash-restore-contract.zh-CN.md   34465 B
docs/en/06-memory-context/phase-3.8.22-g-applied-persistence-idempotency-crash-restore-contract.md    2533 B
docs/zh-CN/06-memory-context/phase-3.8.22-g-applied-persistence-idempotency-crash-restore-contract.md 2395 B
```

该 stem 同时满足 P1（`md`+`zh`）与 P3（双侧镜像），当前 `gap=False`（由 P3 满足）。按 R-5 应判合法并标注 `PAIRED_BY_MIRROR_AND_SIDE_BY_SIDE`。

**但它同时暴露一个 R-5 尚未覆盖的事实**：并排正文 35 KB / 34 KB，镜像只有 2.5 KB / 2.4 KB。两侧体量差 14 倍，**镜像显然不是并排正文的等价物**，更像是指向性摘要。R-5 只要求「标注供审查者核对正文是否一致」，而这里已经可以确认不一致。

因此 R-5 的标注不能只是提示，应升级为**强制审查项**（Owner 已确认此升级）：

```
::warning::PAIRED_BY_MIRROR_AND_SIDE_BY_SIDE <source>: mirror 2533 B vs side-by-side 35411 B
```

强制核对的具体要求：

1. 门禁**不得**把 P3 的存在解释成 P1/P2 正文已被等价镜像；
2. 必须输出可定位的文件路径与审查标记；

4. 若镜像只是摘要、索引或指向性说明，**必须明确记录其文档角色**，不得声称它是完整正文的等价副本；

### 4.5.2c 关键更正：只改缺口扫描不够，两个判据必须同时改

我在 §4 只描述了缺口扫描（`current_bilingual_gaps`）。**这是不完整的**，实测证明：
