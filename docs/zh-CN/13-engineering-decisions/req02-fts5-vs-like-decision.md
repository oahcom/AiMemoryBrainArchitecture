# ADR-REQ02-LEXICAL-001 — 首期本地词法检索通道选择 SQLite FTS5

- 决策 ID：ADR-REQ02-LEXICAL-001
- 需求：REQ-02 / Issue #263
- 状态：**已接受——限定范围的首期决策**
- 决策日期：2026-11-20
- 决策权限：依据 Issue #305 评论 7042461592 所记录的授权书，由 USER-PRINCIPAL-DELEGATED 在本会话行使；本文不声称存在另一位人类签署者。
- 取代：无
- 补充关系：TAB-001 v0.1 §4.3、DOC-TEC-001 v1.0 §4、基准证据 REQ02-LEXICAL-BENCH-001。
- 范围：仅限 local-first 首期的第一个本地共置全文词法检索通道。不构成全系统搜索、向量检索、数据库或生产部署冻结。

## 1. 背景

TAB-001 §4.3 将 SQLite FTS5 列为本地共置词法通道的首个比较对象，并将 Tantivy 列为在索引吞吐、排序控制、分词或语料规模提出需求时可考虑的候选。已合并的可执行证据，在同一确定性合成语料上比较 FTS5 与无索引 SQL `LIKE` 扫描。

该基准范围有限：它为最简单的无索引方案建立可测量基线；没有比较 FTS5 与 Tantivy，也没有证明产品级检索正确性。

## 2. 决策

**选择 SQLite FTS5 作为首期本地全文词法索引**，与 SQLite 存储权威共置，并置于检索/索引接口之后。

该选择受以下强制条件约束：

1. Canonical Memory 始终是权威数据。FTS5 是可重建的派生数据，不得成为事实来源。
2. Scope 和 Permission 必须在未授权候选影响排序、摘要或上下文之前得到执行。
3. 查询可见性必须执行权威 Forget/抑制检查；索引过期或落后于 Fence 时必须 fail closed。
4. 索引更新必须跟随已提交的 canonical 变更，并使用明确的索引水位；该水位与 CanonicalCommitCursor、ForgetFenceGeneration 不同。
5. 重建必须消费 canonical 历史和当前 Forget 状态，不得让已抑制内容复活。
6. 在将该通道视为可用于生产前，Rust 适配器必须通过迁移、更新/删除、重启/重建、授权和 Forget 竞争测试。

## 3. 备选方案与处置

| 方案 | 处置 | 理由及证据边界 |
|---|---|---|
| SQLite FTS5 | **选定**为限定范围的首期词法通道 | 可执行对比中，100/100 个确定性查询的有序结果集完全一致；记录的合成暖缓存负载下，平均延迟为 322.01 μs，而无索引 LIKE 为 10,491.69 μs（32.58×）。它与本地 SQLite 方向共置，不需要独立索引服务/进程。 |
| 无全文索引的 SQL `LIKE` 全表扫描 | **拒绝**作为常规生产词法路径；仅保留为极小数据量回退和回归基线 | 基准同样得到 100/100 一致结果，但平均延迟高 32.58×，查询计划扫描 `docs`，而不是使用全文索引。该证据仅支持拒绝本次测量负载下的无索引路径，不代表拒绝所有 SQL 过滤或带索引的 LIKE 用法。 |
| Tantivy | **暂缓——未拒绝** | TAB-001 已将其列为索引吞吐、排序控制、分词或语料规模提出需求时的候选。当前没有 FTS5 对 Tantivy 的同等基准、适配器集成证据或运维比较。宣称其性能较差会超出证据。若实测需求触发，应重新开启决策并做同等比较。 |
| PostgreSQL 全文检索或外部搜索服务 | **本决议不选用／不在本决议范围内** | 当前 local-first 需求尚不足以证明引入独立服务或运维边界的必要性。这里没有同负载对比数据；这是范围/复杂度选择，不是实测性能淘汰。 |

## 5. 已知限制与明确不主张事项

基准是 LOCAL_ONLY Python `sqlite3` 执行，不是 Rust 原生适配器执行，不是 CI，也不是端到端产品证据。它使用合成精确 token 负载，不能证明：

- CJK 分词质量、生产多语言语料的 tokenizer 适用性、排序相关性或用户可见搜索质量；
- 写入/更新/删除压力、读写并发、崩溃恢复、索引重建成本、存储增长或维护成本；
- Scope/Permission 执行、Forget 抑制、防复活或授权安全；
- 相比 Tantivy 或任何其他成熟搜索产品的优势。

PR #361 关联的 CI 尝试不标记为 PASS：Run `44749692316`，job `136334035195` 返回 `steps=[]`；日志获取返回 HTTP 404 `BlobNotFound`（RequestId `226d976d-001e-00b7-45f8-78b640000000`）。这是平台基础设施证据；本地基准仍明确为 LOCAL_ONLY。

## 6. 重新评估触发条件

出现以下任一可复现事实时，重新开启本 ADR：

- Rust 适配器无法使用 FTS5 满足正确性、迁移或运维要求；
- 代表性多语言相关性/分词要求无法满足；
- 索引吞吐、语料规模、并发更新压力或重建时间超过经约定并实测的范围；
- 在统一 tokenizer、查询语义、语料、结果正确性和负载后，FTS5 与 Tantivy 的同等评估证明存在重大优势；
- 系统不再符合限定的 local-first 部署假设。

任何重新评估都必须保留 canonical 权威性、Scope/Permission 优先过滤、Forget 防复活和可重建性。

## 7. 后果

**正面：**首期单节点词法通道已有明确且可追溯的选择和可复现基线；无需独立搜索服务。

**负面／接受的成本：**FTS5 tokenizer 和排序行为成为限定范围内的依赖；索引维护、迁移、重建和正确性门禁仍是实现责任。

**本决议未决定：**向量检索、数据库权威、是否采用 Tantivy、排序策略、生产就绪状态和全系统技术冻结。
