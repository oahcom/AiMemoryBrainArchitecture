## 1. The environment block and how it was removed

### 1.1 The block

`GAP-BASELINE-002.md` records:

> This machine's `gcc` is an incomplete MinGW install: `gcc.exe` exists but `cc1` does not, so no C code compiles. Any crate that pulls in `libsqlite3-sys` (via `rusqlite` with the `bundled` feature) cannot be built or tested here.

Reproduced:

```
gcc.exe: fatal error: cannot execute 'cc1': CreateProcess: No such file or directory
error occurred in cc-rs: command did not execute successfully
  "gcc.exe" ... "-c" "sqlite3/sqlite3.c"
```

### 1.2 How it was removed

A complete `zig` is present (the `ziglang` package ships `zig.exe`). Using `zig cc` as the C compiler:

```bash
export CC="<path>/zigcc.bat"     # forwards to zig cc
export AR="<path>/zigar.bat"     # forwards to zig ar
cargo test --workspace
```

The wrapper does two necessary things:

1. `--target=x86_64-pc-windows-gnu` -> `--target=x86_64-windows-gnu` (zig rejects the former)
2. appends `-fno-sanitize=undefined` (zig cc at -O0 injects UBSan calls into sqlite3.c, and rustc's link line carries no ubsan runtime)

**This is an environment fix, not a code change.** Not one byte of the repository was modified.
